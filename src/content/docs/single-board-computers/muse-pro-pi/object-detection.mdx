The Muse Pro Pi can run computer-vision workloads locally on its RISC-V SoC and
NPU. This tutorial deploys the official SpacemiT AI SDK, compiles the vision
component, downloads the sample models, and runs YOLOv8 object detection on an
image and a video.

## Part 1: workspace and SDK setup

The SDK uses Git submodules to manage its components — vision, ASR, LLM, and
others — so clone it with `--recurse-submodules`.

Open a terminal on the Muse Pro Pi and run:

```bash title="Set up the workspace"
# 1. Create a dedicated workspace
cd ~
mkdir muse-pi-vision-article
cd muse-pi-vision-article

# 2. Clone the SDK
git clone --recurse-submodules https://github.com/spacemit-com/ai-sdk.git
cd ai-sdk
```

## Part 2: build the vision component

The full SDK is large, but this project only needs the computer-vision module. The
SDK provides its own build environment.

```bash title="Build the vision component"
# 1. Load the build environment
source build/envsetup.sh

# 2. Enter the vision directory and build it
cd vision && mm
```

The first build can take a while: it installs dependencies and compiles C++ code.
Run `source build/envsetup.sh` from the SDK root in each new shell before using
the build commands.

## Part 3: download models and assets

The SDK's scripts fetch pre-compiled ONNX models and sample test images.

```bash title="Download models and sample assets"
# 1. Return to the SDK root
cd ~/muse-pi-vision-article/ai-sdk

# 2. Download models into ~/.cache/models/vision/
bash vision/scripts/download_all_models.sh

# 3. Download test assets into ~/.cache/assets/
bash vision/scripts/download_assets.sh
```

Verify that the sample images arrived:

```bash
ls ~/.cache/assets/image/
```

## Part 4: run YOLOv8 object detection

Locate the compiled executable. The build system stages it under `output/`:

```bash
find output/ -name "yolov8"

# Output: output/staging/bin/yolov8
```

Run the sample image through YOLOv8:

```bash title="Run YOLOv8 on the sample image"
cd ~/muse-pi-vision-article/ai-sdk

./output/staging/bin/yolov8 vision/examples/yolov8/config/yolov8.yaml \
  --image ~/.cache/assets/image/005_kitten.jpg --output kitten_detected.jpg
```

## Troubleshooting the real-world hurdles

Two issues showed up during the source test. Both are configuration or library
problems, not mistakes in the build commands.

| Issue | Cause | Fix |
| --- | --- | --- |
| Not enough available AI cores | The SoC has eight cores, but only four (Cluster0) support the AI acceleration instructions. The default config tries to use eight threads. | Edit `vision/examples/yolov8/config/yolov8.yaml` and change `num_threads: 8` to `num_threads: 4`. |
| `tcm buffer acquire failed for core id 1` | A known bug in `spacemit-ort` (ONNX Runtime) version 2.0.3 from the Bianbu repository. It fails to allocate Tightly Coupled Memory correctly across multiple cores. | Upgrade to `spacemit-ort` 2.0.5 manually, as described below. |

## Fixing the TCM bug (spacemit-ort 2.0.5)

Download `spacemit-ort.riscv64.2.0.5.tar.gz` from the SpacemiT ONNX Runtime
GitHub Releases page (v2.0.5) on your computer, then transfer it to the board:

```bash
scp spacemit-ort.riscv64.2.0.5.tar.gz user@<board-ip>:~/
```

On the board, extract it:

```bash
cd ~
mkdir -p spacemit-ort-2.0.5
tar -xzf spacemit-ort.riscv64.2.0.5.tar.gz -C spacemit-ort-2.0.5
```

The source article stored the library under the author's home directory. Use your
own home directory instead:

```bash title="Run YOLOv8 with the patched library"
LD_LIBRARY_PATH="$HOME/spacemit-ort-2.0.5/spacemit-ort.riscv64.2.0.5/lib:$LD_LIBRARY_PATH" \
./output/staging/bin/yolov8 vision/examples/yolov8/config/yolov8.yaml \
  --image ~/.cache/assets/image/005_kitten.jpg --output kitten_detected.jpg
```

A successful run prints the model path, the detection count, and the result:

```text
Loading image: /home/<user>/.cache/assets/image/005_kitten.jpg
SpaceMIT EP initialized: /home/<user>/.cache/models/vision/yolov8/yolov8n_no_dfl.q.onnx
Detected 1 objects:
Class 15, Score: 0.7434, Box: [202.9875,65.8378,579.6367,667.2567]
Result image saved to: kitten_detected.jpg
```

Copy the result back to your computer with `scp` if you want to inspect the
bounding box on a larger screen.

## Next steps: video processing

With the environment working and the TCM bug bypassed, the board can process video
frame by frame. ByteTrack adds tracking IDs to the detected objects.

### Step 1: edit the ByteTrack config

```bash
nano vision/examples/bytetrack/config/bytetrack.yaml
```

Find `num_threads` and change it from 8 to 4, for the same AI-core reason as the
YOLOv8 configuration:

```yaml
num_threads: 4
```

Save and exit (`Ctrl+X`, then `Y`, then `Enter`).

### Step 2: run video tracking

```bash title="Run ByteTrack on the sample video"
LD_LIBRARY_PATH="$HOME/spacemit-ort-2.0.5/spacemit-ort.riscv64.2.0.5/lib:$LD_LIBRARY_PATH" \
./output/staging/bin/bytetrack vision/examples/bytetrack/config/bytetrack.yaml \
  --video ~/.cache/assets/video/001_crowd.mp4 --output video_tracked.mp4
```

The tracker processes the video frame by frame and draws a tracking ID on each
detected object.

## Notes before you run this

- The commands assume the SDK and model-download scripts still use the paths shown
  here. Check the SDK's current documentation if a script has moved.
- Model files are large. Make sure the board has enough free storage before
  downloading them.
- The AI-core limit is a hardware/toolchain detail, not a general rule for every
  RISC-V board. Keep `num_threads: 4` for this workflow unless the vendor's newer
  configuration says otherwise.
- The patched library is loaded with `LD_LIBRARY_PATH` for that command only. It
  does not permanently replace the system package.
- These instructions have not been reproduced for this wiki. Treat the expected
  output as an example, not a guarantee.
