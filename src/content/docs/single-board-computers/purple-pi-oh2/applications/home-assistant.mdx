Home Assistant is an open-source home-automation platform. It runs on the local
network, integrates smart devices, and provides automations and a dashboard. This
guide runs the official container image with Docker.

## Verify Docker

```bash
docker -v
sudo systemctl status docker
docker run hello-world
dpkg --print-architecture
```

The architecture command should report `arm64` for the Purple Pi OH2. The
`hello-world` container confirms that the daemon can pull and run images.

## Create the configuration directories

```bash
sudo mkdir -p /opt/homeassistant/config
sudo mkdir -p /opt/homeassistant/localtime
```

Set ownership for your user instead of making the directory world-writable:

```bash
sudo chown -R $USER:$USER /opt/homeassistant
sudo chmod -R 755 /opt/homeassistant
```

<Callout variant="warning" title="Do not use chmod 777">
  The source guide used `chmod -R 777`. That lets every local user modify the
  Home Assistant configuration. Use ownership and `755` permissions unless your
  container setup specifically requires otherwise.
</Callout>

## Run the container

```bash title="Start Home Assistant"
docker run -d \
  --name homeassistant \
  --privileged \
  --restart=unless-stopped \
  -e TZ=Asia/Colombo \
  -v /opt/homeassistant/config:/config \
  -v /run/dbus:/run/dbus:ro \
  --network=host \
  ghcr.io/home-assistant/home-assistant:stable
```

Replace `Asia/Colombo` with your own timezone. Verify the container image name
against the current Home Assistant documentation before relying on it for an
unattended deployment.

<Callout variant="caution" title="Privileged mode and host networking">
  `--privileged` and `--network=host` give the container broad access to the host.
  The source uses them for USB/Zigbee device access and local discovery. Review
  the security implications and limit the container's access where possible.
</Callout>

## Manage the container

| Task | Command |
| --- | --- |
| Stop | `docker stop homeassistant` |
| Start | `docker start homeassistant` |
| Restart | `docker restart homeassistant` |
| Logs | `docker logs homeassistant` |
| Remove container (keeps config) | `docker rm -f homeassistant` |
| Pull the latest image | `docker pull ghcr.io/home-assistant/home-assistant:stable` |

## Update Home Assistant

```bash
docker stop homeassistant
docker rm homeassistant
docker pull ghcr.io/home-assistant/home-assistant:stable
```

Then run the `docker run` command again with the same volumes. Back up
`/opt/homeassistant/config` before updating.

## Troubleshooting

| Issue | Check |
| --- | --- |
| Port 8123 does not respond | `docker ps` and `docker logs homeassistant` |
| Container restarts repeatedly | Check configuration and logs; restore a backup if needed |
| USB/Zigbee device not detected | Device permissions and the `--privileged` trade-off |
| Setup wizard appears again | The `/config` volume may not be mapped to persistent storage |
